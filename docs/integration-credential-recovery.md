# 集成账户凭据恢复

服务端调用方在首次开户响应丢失或本地事务回滚后，可通过
`POST /api/integrations/credentials/recover` 取回已存在的原密钥。
沿用 `/api/integrations/*` 的集成身份认证和集成级限流；浏览器和普通用户无调用权限。

请求包含 `external_user_id`、`expected_user_id`、`expected_token_id`。三者必须匹配
当前认证集成名下的账户。账户和令牌必须启用、未过期，令牌所有者必须一致。
接口仅接受 `bounded-v1` 协议、用户与令牌均无消费、没有请求授权记录的初始化失败账户。
接口拒绝已暂停计费的账户。缺失账户、错误映射和禁用状态均不会自动修复。

成功响应沿用余额结构，并在 `token.api_key` 返回原密钥，标记 `Cache-Control: no-store`。
调用方须在服务端直接加密持久化，禁止写入日志、审计详情或浏览器响应。
普通开户重放仍不返回密钥。恢复不创建账户、不轮换令牌、不改变额度或消费记录，重复调用返回原密钥。

调用方负责管理员授权、恢复原因、审计，以及自己的额度账本核对。本接口不代表允许重新赠额。
无数据库结构或环境配置变化；回滚后新恢复调用会失败，既有开户与已保存凭据继续可用。
